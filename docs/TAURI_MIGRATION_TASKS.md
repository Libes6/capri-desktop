# Capri: план перехода с Electron на Tauri

Дата: 2026-10-28.
База: ветка `dev`, коммит `ee1f97d` (CAPRI-01…12 выполнены).
Образец Tauri-проекта пользователя: `/Users/maksimkulakov/pet/m code` (Густаф: Tauri 2, `tauri-plugin-updater`, `release-build.yml`, Node-сайдкар).

## Главная идея

Не переписывать всё разом. Переход идёт тремя этапами:

1. **Подготовка внутри Electron.** Отделяем логику от Electron, пока всё работает и проверяется существующими тестами.
2. **Tauri-оболочка с той же логикой.** Rust отвечает за окна, трей, ОС-события и обновления. Остальная логика продолжает работать как Node-сайдкар, renderer переносится почти без изменений.
3. **Постепенный перенос сайдкара на Rust,** модуль за модулем, по мере необходимости.

Electron-версия остаётся рабочей и выпускаемой до задачи TAURI-14. Каждый шаг можно остановить без потери уже сделанного.

## Текущее состояние (замер 2026-10-28)

- Main-процесс: около 5 200 строк JS. Самые крупные: `main.js` (1 476), `labels.js`, `updates.js`, `launch.js`, `llm.js`.
- Renderer: около 13 700 строк обычного JS без фреймворка. Overlay (`index.html`) и окно настроек (`settings.html`).
- 65 IPC-каналов в `main.js`. Основные группы: `overlay:*`, `screens:*`, `config:*`, `settings:*`, `updates:*`, `chat:*`, `setup:*`, `apps:*`, `files:*`, `look:*`.
- Около 27 разных API Electron: `screen`, `powerMonitor`, `globalShortcut`, `safeStorage`, `Tray`, `Menu`, `shell`, `desktopCapturer`, `nativeImage` и другие.
- Внешние процессы: `windows.ps1` (Windows), Swift-helper `capri-windows` (macOS), `xprop`/`xwininfo` (Linux X11).
- HTTP-мост для хуков ассистентов: `bridge.js`, `127.0.0.1:CAPRI_PORT`.
- **Хуки ассистентов запускаются через бинарник Electron** (`ELECTRON_RUN_AS_NODE=1 "<Capri>" hook.js`, см. `scripts/install-hooks.js:53`). В Tauri такого Node нет. Это отдельная обязательная задача.
- Обновления: `electron-updater` + своя подмена `.app` на macOS (CAPRI-11).

## Ключевые риски, которые проверяются первыми

1. **Прозрачный overlay, сквозь который проходят клики.** Electron умеет пропускать клики и одновременно передавать странице движение мыши (`setIgnoreMouseEvents(true, { forward: true })`). В Tauri есть только `set_ignore_cursor_events(bool)` без передачи движения. Придётся опрашивать курсор из Rust (`cursor_position()`) и включать или выключать пропуск кликов по маске персонажа. На Linux так уже сделано в Electron-версии.
2. **WebGL и прозрачность в системных webview.** На macOS это WKWebView (Safari), на Linux WebKitGTK, на Windows WebView2 (Chromium). На WebKitGTK прозрачность и WebGL заметно капризнее. На macOS для прозрачного окна нужен `macOSPrivateApi`.
3. **Node для логики и хуков.** Пока логика живёт в сайдкаре, Node нужно поставлять внутри приложения. Полагаться на системный Node нельзя: у части пользователей Claude Code поставлен без Node.
4. **Миграция данных пользователя.** Отличаются путь к профилю, зашифрованные API-ключи (`safeStorage`) и установленные хуки, которые указывают на путь к Electron.

## TAURI-00. Прототип overlay: проверка главного риска (go/no-go)

**Приоритет:** P0. **Зависимости:** нет. **Ветка:** `spike/tauri-overlay`, в `main`/`dev` не мержится.

**Цель:** за минимальное время понять, можно ли на Tauri получить тот же overlay на трёх ОС. Если нельзя, переход не начинается.

**Работа:**

- Минимальное Tauri 2 приложение: одно прозрачное окно без рамки на весь экран, всегда поверх (уровень как у Electron `screen-saver`), видно на всех рабочих столах и Spaces, без иконки в панели задач и Dock.
- Внутри — настоящий спрайт персонажа на WebGL из `src/renderer/js/sprite.js` с анимацией 12 fps. Копия файлов, без остальной логики.
- Пропуск кликов: Rust раз в 30–50 мс берёт позицию курсора и прямоугольник/маску персонажа от страницы, затем вызывает `set_ignore_cursor_events`. Проверить drag персонажа мышью.
- Несколько мониторов и scaleFactor: окно на нужном экране, переход между экранами.
- Замерить CPU/GPU в idle тем же методом, что `scripts/perf-probe.js`.

**Готово, когда:** есть короткий отчёт `docs/TAURI_SPIKE.md` с таблицей по ОС (macOS arm64 вживую; Windows и Linux X11 хотя бы в CI с запуском и скриншотом): прозрачность, WebGL, пропуск кликов, drag, поверх полноэкранных окон, Spaces/рабочие столы, нагрузка. Явное решение: идти дальше, идти с ограничениями (например без Linux) или остаться на Electron.

**Вне задачи:** логика, трей, настройки, хуки.

**Готово, когда:** все существующие тесты и smoke проходят; ядро загружается в чистом `node` с фейковой платформой; поведение Electron-версии не изменилось (ручная проверка трея, настроек, чата, обновлений).

## TAURI-02. Единый протокол команд и контрактные тесты

**Приоритет:** P1. **Зависимости:** TAURI-01.

**Цель:** 65 IPC-каналов превращаются в один описанный протокол, который одинаково обслуживают Electron IPC и будущий Tauri.

**Работа:**

- Описать все команды и события в одном файле (`src/protocol.js` или JSON-схема): имя, параметры, ответ, кто вызывает (overlay, окно настроек), направление (запрос/событие).

- Контрактные тесты: для каждой команды — корректный вызов, неверные параметры, вызов из «чужого» окна.

**Готово, когда:** список команд полный и сверен с `main.js`, контрактные тесты зелёные, smoke проходит.

## TAURI-04. Каркас Tauri и Node-сайдкар

**Приоритет:** P1. **Зависимости:** TAURI-00 (решение «идём»), TAURI-02, TAURI-03.

**Цель:** Tauri-приложение запускает ядро Capri как сайдкар и показывает overlay.

**Работа:**

- `src-tauri/` по образцу Густафа: `tauri.conf.json` (identifier `capri.desktop`, productName Capri), `Cargo.toml`, capabilities по принципу минимальных прав.
- Сайдкар: ядро из TAURI-01 с Node-реализацией платформы, где нативные операции (окна, трей, экраны) превращаются в запросы к Rust. Связь Rust ↔ сайдкар — JSON-RPC по stdin/stdout.
- **Поставка Node:** собрать сайдкар в один исполняемый файл на каждую платформу (Node SEA или `bun build --compile`), положить как `externalBin`. Сравнить размер и время старта, выбор записать в docs.
- Rust-команда `invoke` пробрасывает вызовы renderer в сайдкар, события сайдкара — в нужное окно.
- Жизненный цикл: сайдкар перезапускается при падении (лимит попыток), завершается вместе с приложением, single-instance (`tauri-plugin-single-instance`).

**Готово, когда:** `npm run tauri dev` поднимает overlay с персонажем; команды из renderer доходят до ядра и обратно; падение сайдкара не роняет окно.

## TAURI-08. Запуск хуков ассистентов без Electron

**Приоритет:** P1, блокирует выпуск. **Зависимости:** TAURI-04. Параллельно с 05–07.

**Проблема:** установленные хуки вызывают `ELECTRON_RUN_AS_NODE=1 "<путь к Capri>" capri-hook.js`. В Tauri этого Node нет.

**Работа:**

- Маленький отдельный исполняемый файл `capri-hook` (Rust, без зависимостей от webview): читает событие хука из stdin и отправляет его в HTTP-мост `127.0.0.1:CAPRI_PORT`, как `hooks/capri-hook.js`. Варианты для Codex и Antigravity — флагами.
- Поставлять его в пакете (`externalBin`), путь стабильный между обновлениями.
- Установщики хуков (`scripts/install-hooks*.js` и логика в ядре) пишут команду с этим файлом. Старые записи с путём Electron распознаются и заменяются при первом запуске Tauri-версии.
- Поведение при выключенном Capri такое же, как сейчас: хук не задерживает ассистента.

**Готово, когда:** на временном профиле Claude Code, Codex и Antigravity хуки доходят до персонажа; старые записи заменяются; тесты на разбор и отправку событий.

## TAURI-09. Миграция данных пользователя

**Приоритет:** P1, блокирует выпуск. **Зависимости:** TAURI-07, TAURI-08.

**Работа:**

- Профиль: Electron хранит данные в `app.getPath('userData')` (`…/Capri`), Tauri — в каталоге по identifier. При первом запуске скопировать `config.json`, память, напоминания, историю чата, bond; старые файлы не удалять.

- Автозапуск: снять старую запись Electron, поставить новую, если был включён.

**Готово, когда:** на копии реального профиля (во временном каталоге) после первого запуска Tauri-версии все настройки, память и ключи на месте; повторный запуск ничего не дублирует.
